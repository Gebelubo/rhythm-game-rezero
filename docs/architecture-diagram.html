Dica: as rotinas “permitidas” pela disciplina estão concentradas em src/funcs/cg_lib.py; as telas usam essas primitivas para desenhar UI, splash e elementos do jogo.

Máquina de estados (alto nível)

stateDiagram-v2 [*] --> splash splash --> menu: tempo / tecla / clique menu --> lobby: Play menu --> tutorial menu --> settings menu --> character_select menu --> shop lobby --> playing: ENTER numa fase playing --> results: música termina results --> lobby: ESC results --> playing: ENTER (replay) lobby --> menu: ESC (volta) tutorial --> menu: ESC/clique settings --> menu: ESC lobby --> recording: ADM mode + fase fixa recording --> menu: ESC recording --> menu: música termina (salva beatmap)
Estados são controlados por RhythmGame.run() em src/main.py.

Fluxo de dados (Input → lógica → render)

sequenceDiagram participant P as Player participant PG as Pygame (events/mixer) participant RG as RhythmGame (src/main.py) participant BK as Music Backend (src/music_backend) participant SC as Screens (src/screens/*) participant CG as CG Lib (src/funcs/cg_lib.py) P->>PG: teclas / mouse PG->>RG: eventos (KEYDOWN/MOUSE) RG->>SC: chama update/draw do estado atual RG->>BK: detect_beats() ou load_beatmap() BK->>RG: eventos (time,direction) + bpm + duration RG->>RG: apply_difficulty() + cria Notes RG->>PG: mixer.music.play() SC->>CG: rasterização / scanline / textura / viewport SC->>PG: blit surfaces / flip
No gameplay, o hit/miss e score dependem de music_time() (posição do mixer) e das janelas de timing em src/config.py.
